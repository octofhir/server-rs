## Why OctoFHIR

<CardGrid>
  <Card title="One binary, one database">
    Server, search engine and console ship as one Rust binary on PostgreSQL. Resource tables
    are created on demand, so loading an Implementation Guide needs no migrations.
  </Card>
  <Card title="Spec-first">
    FHIR R4, R4B, R5 and R6. 98.7% (1552 of 1572) on the FHIR262 conformance suite.
  </Card>
  <Card title="A console for developers">
    REST, SQL, GraphQL, FHIRPath, CQL and notebooks in one place, with completion that knows
    your data: type `subject=` and pick a patient by name.
  </Card>
  <Card title="Keyboard-first">
    `⌘K` jumps anywhere (`Patient/123` opens it), `g` + a letter switches tools, `j`/`k` walk
    lists and `?` shows every shortcut.
  </Card>
</CardGrid>

## What's inside

<CardGrid>
  <Card title="FHIR REST API">
    CRUD, history, conditional operations, transactions and batches; search with chains,
    `_include`/`_revinclude`, composites and modifiers.
  </Card>
  <Card title="Query it your way">
    GraphQL generated from the FHIR schemas, SQL on FHIR `ViewDefinition`s, Bulk Data
    `$export`, and a SQL console with a Postgres language server.
  </Card>
  <Card title="Terminology and validation">
    `$expand`, `$validate-code`, `$subsumes` and `$translate`; validation against the profiles in
    the packages you load.
  </Card>
  <Card title="Security">
    OAuth 2.0 and SMART on FHIR, external identity providers, access policies as scripts and an
    audit trail.
  </Card>
</CardGrid>
