# OctoFHIR server v0.0.8

Fix the UPS-RS filtered subscription request so Task Managers receive the
OctoFHIR source namespace in the standard `filter` query parameter.

- Send `filter=00741204=<subscription_prefix>*` together with `deletionlock=true`
  on the Filtered Worklist Subscription resource, as specified by DICOM PS3.18
  11.10.1.2. A standalone `ProcedureStepLabel` query parameter could be ignored
  and broaden notifications and deletion locks beyond the intended namespace.
- Verify the complete subscription query, the persisted source namespace and
  the empty Subscribe request body in the independent UPS protocol tests,
  including polling fallback and WebSocket recovery.
- Recheck completion, result publication and queued cancellation against
  Clarus 0.3.2-beta using the corrected subscription request.

Task Manager compatibility: the archive must honor the label-prefix filter.
Clarus 0.3.1-beta and 0.3.2-beta accept the standard request but do not deliver
notifications for wildcard-prefix filters; exact-label filters work. The
completion scenario succeeds through state polling and does not establish
working wildcard notifications or deletion locks in those Clarus versions.

Existing UPS configuration applies without a database migration.

Download Linux x86_64/aarch64 or macOS x86_64/aarch64 archives and verify SHA256SUMS.
Linux GNU builds require glibc 2.35 or newer; macOS targets version 13 or newer.
Archives include the embedded console, example configuration and DICOM guides.
PostgreSQL and deployment credentials are required.

Docker: `ghcr.io/octofhir/octofhir-server:0.0.8` for linux/amd64 and linux/arm64.

Documentation: https://octofhir.github.io/server-rs/dicom/
