# OctoFHIR server v0.0.6

Expand the authenticated DICOMweb gateway with standard Search/Retrieve routes,
metadata representations and an explicit implementation conformance statement.

- All six QIDO search routes, fresh authorized response attributes, matching,
  includefield, live pagination and bounded query budgets.
- DICOM JSON and Native DICOM Model XML, weighted Accept/query negotiation,
  UTF-8 metadata and strict ascending frame lists.
- Base OPTIONS/WADL capabilities with genuine CORS preflight handled separately.
- Streamed study/series DICOM and native bulk collections assembled only from
  admitted instances. Late PACS arrivals cannot expand an in-flight collection.
- Study/series renderings and all thumbnail levels through PACS; opaque bulk
  references under the configured DICOMweb service and bounded native InlineBinary.
- Request-wide authorization snapshots, fresh Patient/SOP checks before upstream
  reads, flat multipart output, cancellation and cumulative byte/time bounds.
- Synthetic multiframe and JPEG Baseline fixtures extend the Orthanc/dcm4chee
  matrix; no image payload is stored in PostgreSQL or S3 through the connector.
- Accept a single DICOM JSON object for instance metadata, as returned by some
  PACS, while retaining array validation for study/series metadata.
- Raise the default per-PACS metadata limit from 8 to 64 MiB and the gateway
  query/metadata-response budget from 32 to 128 MiB. Both remain configurable.
  Gateway metadata limit failures return HTTP 413 with a specific diagnostic.

`max_query_studies` and `max_query_bytes` are available starting with this release;
v0.0.5 rejects these configuration keys. Existing explicit metadata/query limits
remain in effect until changed in the deployment configuration.

Database upgrade coverage starts from the published v0.0.5 image and verifies
that existing migration checksums remain unchanged on upgrade and repeated
startup. A checksum mismatch indicates a different database/build history and
must be investigated; this release does not bypass migration validation.

FHIR Mapping Language reference resolution uses caller-authorized internal reads,
including conditional references, rather than bypassing the caller's access policy.

Rendering and codec/transfer-syntax conversion depend on the configured PACS.
The bundled conformance statement describes the supported profile and limits;
this release does not claim every DICOM/IHE actor or general viewer certification.
STOW, UPS Performer execution, semantic SR interpretation and general
Binary/Attachment S3 storage remain outside this gateway delivery. Existing
UPS Requestor/Watcher and custom FHIR operations are retained.

Normal FHIR/DICOMweb clients remain portable through ImagingStudy/Endpoint/Task
and ordinary FHIR REST. See the integration guide and standard client example.

Download Linux x86_64/aarch64 or macOS x86_64/aarch64 archives and verify SHA256SUMS.
Linux GNU builds require glibc 2.35 or newer; macOS targets version 13 or newer.
Archives include the embedded console, example configuration and guides, including
the conformance statement. PostgreSQL and deployment credentials are required.

Docker: `ghcr.io/octofhir/octofhir-server:0.0.6` for linux/amd64 and linux/arm64.
