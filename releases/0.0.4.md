# OctoFHIR server v0.0.4

Connect clinical FHIR resources to external DICOMweb archives and load private
implementation guides through reusable, database-backed S3 providers.

## Storage providers and private IGs

- Manage named StorageProvider resources through the administrator API and the
  console's System → Storage providers page. Seed missing providers from TOML;
  later database edits survive restarts.
- One S3/SigV4 driver supports configurable endpoints, signing regions and path or
  virtual-hosted bucket addressing. AWS S3, R2, B2, Garage and RustFS configuration
  examples are documented; only RustFS has a real-backend container acceptance test.
- Credentials are environment references or AES-256-GCM encrypted stored keys using
  OCTOFHIR_CONFIG_KEY. API responses and provider history never return key material.
  Administrative writes use optimistic concurrency and record redacted history.
- IG objects reference provider/bucket/key and mandatory SHA-256, with optional
  object version. Verified caches can boot without credentials or network access.
- Read-only package directories and local package.tgz archives support standalone
  paths and mounted volumes. Registry-offline startup resolves explicitly supplied,
  installed and cached dependencies. Unmodified RuCore fixtures exercise actual
  profile slicing and local terminology validation.

## DICOM integration

- Opt-in named metadata import, QIDO discovery and durable reconciliation into
  ImagingStudy/Endpoint with explicit assigning-authority patient matching.
- Optional authenticated DICOMweb gateway checks current Patient/study policy and
  an independently attested instance manifest. Multipart object/frame/bulk bytes
  stream with backpressure, cancellation, concurrency, size and time bounds.
- UPS-RS Requestor/Watcher maps existing authorized Task inputs to stable workitem
  UIDs, recovers ambiguous creation/missed events and distinguishes cancellation
  requests from confirmed cancellation. Performers and inference run externally.
- Configured output mappings publish DiagnosticReport/DocumentReference links with
  Task and Provenance. Metadata/security annotations are preserved. SR/SEG objects
  and image pixels remain in PACS, never in PostgreSQL or S3 through this connector.

Retrieval is tested against Orthanc and dcm4chee. UPS is tested against dcm4chee and
an independent protocol peer. The gateway deliberately does not expose unrestricted
archive searches or whole-study/series binary export. This release does not claim
complete WADO/UPS/IHE or OHIF/Stone compatibility. General Binary/Attachment S3 blob
storage and semantic SR interpretation remain separate work.

## Downloads and deployment

Download the archive for Linux x86_64/aarch64 or macOS x86_64/aarch64 and verify it
against SHA256SUMS. Each archive includes the server with its embedded console,
Apache-2.0 license, example configuration and integration guides. A PostgreSQL
server and deployment-specific authentication/credentials are required.
Run `./octofhir-server --help` for CLI options; `--config /path/to/octofhir.toml`
selects a local configuration file and `--version` prints the installed version.

Linux GNU binaries are built on Ubuntu 22.04 with vendored OpenSSL (glibc 2.35 or
newer); macOS builds target macOS 13 or newer. GitHub also provides the source archives.

Docker: `ghcr.io/octofhir/octofhir-server:0.0.4` provides linux/amd64 and linux/arm64.
The release workflow builds native binaries and images from the exact tag, smoke
tests executable startup and publishes checksums only after every build and main
CI for the exact source commit succeed.

Documentation: https://octofhir.github.io/server-rs/storage-providers/
DICOM guide: https://octofhir.github.io/server-rs/dicom/

The package-S3 source shape introduced in this release is provider-based. The
unreleased inline endpoint/credential package draft is not a supported format.
PostgreSQL migrations run automatically; back up a deployed database before upgrading.
