# OctoFHIR server v0.0.7

Keep UPS Requestor/Watcher processing available when a PACS cannot open the
WebSocket notification channel, and deliver the SQL, notebook and outbound-access
hardening added since v0.0.6.

- Fall back to per-task polling only after a filtered deletion-lock subscription
  succeeds. Failed subscriptions leave creation queued.
- Require a live, fenced subscription readiness lease in both transport modes;
  a persisted `poll_only` flag cannot authorize creation by itself.
- Keep retrying WebSocket connections while renewing polling readiness and
  releasing completed workitem subscriptions. Restore notifications automatically
  and reconcile subscription releases after resubscription.
- Renew readiness through the PostgreSQL connection holding the source advisory
  lock, so losing that connection stops the old watcher from renewing its lease.
- Cover polling completion/output publication, rejected subscriptions, stale
  readiness, terminal deletion-lock release and WebSocket recovery with an
  independent protocol peer. Isolate test databases from the process-global
  canonical manager.
- Restrict console and application SQL, notebook execution/export and untrusted
  notebook output. Constrain headless REST cells to relative paths on this
  server's FHIR API, with redirects disabled.
- Apply outbound URL checks across notification and gateway paths; include local
  dependency security backports and refreshed console/documentation dependencies.
- Include vendored Rust patches in Docker builds and add a Codespaces quick start.

On upgrade, startup adds the `dicom_ups_sources.poll_only` column through a new
migration. Existing migration files and checksums are unchanged. No new UPS
configuration key is required. Polling fallback still requires the PACS to accept
the filtered deletion-lock subscription; it does not replace that protection.

Console SQL requires the configured privileged role, defaulting to `admin`.
Notebook execution/export follows the caller's Notebook read authorization.
Headless REST cells using absolute URLs or paths outside the local FHIR API must
be updated to relative FHIR paths.

Download Linux x86_64/aarch64 or macOS x86_64/aarch64 archives and verify SHA256SUMS.
Linux GNU builds require glibc 2.35 or newer; macOS targets version 13 or newer.
Archives include the embedded console, example configuration and DICOM guides.
PostgreSQL and deployment credentials are required.

Docker: `ghcr.io/octofhir/octofhir-server:0.0.7` for linux/amd64 and linux/arm64.
